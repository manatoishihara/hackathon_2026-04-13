Codex MCP で実装レビューを実行する。

引数: $ARGUMENTS
  - なし: 直近の変更（git diff）をレビュー
  - ファイルパス: 指定したファイルをレビュー
  - "plan": 計画段階のレビュー（まだコードを書いていない）

## プロセス

### Plan レビュー（$ARGUMENTS == "plan"）

1. `tasks/todo.md` の次に着手するタスクを読む
2. そのタスクの実装方針を整理して Codex に渡す
3. Codex の指摘を反映
4. 方針が固まったら実装に進む

### コードレビュー（デフォルト）

1. `git diff` または $ARGUMENTS で指定されたファイルの差分を取得
2. 差分を Codex MCP に渡して以下の観点でレビュー依頼:
   - 設計上の問題（責務の分離、拡張性）
   - バグ・エッジケース
   - セキュリティ懸念
   - パフォーマンス懸念
   - `.claude/rules/` のルール違反
   - テストカバレッジ不足
3. Codex の指摘を重要度（Critical / Major / Minor）で整理
4. Critical と Major は修正してから再レビュー、Minor は lesson として記録

## Codex への依頼テンプレート

```
以下のコード変更をレビューしてください。

## プロジェクト概要
Routeful - AI 旅行計画ツール。LLMの意味理解 + 外部APIの構造化データで
実在し時間的に成立するプランを生成する。

## 本変更の目的
[タスク番号と短い説明]

## 遵守すべきルール
- CLAUDE.md
- .claude/rules/[該当するルールファイル]

## 差分
[git diff の出力]

## レビュー観点
- 設計上の問題
- バグ・エッジケース
- ルール違反
- テストの十分性

重要度（Critical / Major / Minor）を付けて指摘してください。
```

## 修正を反映したら

1. 再度 `/codex-review` を実行
2. Critical と Major が 0 になるまでループ
3. Minor のみなら lesson に記録して差分をユーザに提示（コミットはユーザが手動で行う）
