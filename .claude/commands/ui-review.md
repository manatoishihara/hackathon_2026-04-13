UI 実装後に実行するレビューコマンド。スラッシュコマンドとして `/ui-review` で呼ぶ。

引数: $ARGUMENTS（対象コンポーネントのファイルパス、未指定なら直近の変更ファイル）

## レビュー観点

対象: $ARGUMENTS

以下の観点でレビューし、違反があれば具体的な修正提案を出せ。

### 1. アンチパターン違反（表層）

- [ ] Inter フォントを使っていないか
- [ ] Lucide アイコンのみを使っていないか（Phosphor 推奨）
- [ ] 青→紫のAIグラデーションを使っていないか
- [ ] shadcn/ui のデフォルトテーマそのままになっていないか
- [ ] 数字を `Intl.NumberFormat('ja-JP')` で整形しているか
- [ ] 絵文字をUIの意味伝達に使っていないか

### 2. 情報設計（構造）

- [ ] 画面の主役が明確か（サイズ・ウェイトでメリハリがある）
- [ ] 全要素が均一に並んでいないか
- [ ] 色に役割がついているか（同じ色に複数の意味を持たせていないか）
- [ ] 便利そうな要素を全部載せていないか

### 3. UI 耐久性

- [ ] 長文テキスト（30 文字以上の名前、3 行以上の説明）で崩れないか
- [ ] 0 件 / Empty State で画面が成立するか
- [ ] ローディング状態・エラー状態が実装されているか
- [ ] 参加者が 2 人〜5 人で破綻しないか（該当コンポーネントなら）

### 4. アクセシビリティ

- [ ] タッチターゲットが 44x44 以上
- [ ] フォームラベルが関連付けられている（htmlFor / id）
- [ ] フォーカスインジケータが視覚的に明確
- [ ] 色のコントラスト比が WCAG AA 以上

### 5. パフォーマンス

- [ ] `"use client"` が必要最小限か
- [ ] 画像に `next/image` を使っているか
- [ ] 大きなライブラリをダイナミックインポートしているか（Map 等）

## 出力形式

各観点について、

- ✓ OK な点
- ⚠ 気になる点（重要度: Critical / Major / Minor）
- 修正提案（具体的なコード差分）

の 3 項目で報告せよ。Critical が 1 つでもあれば Codex レビューを走らせる前にまず修正すべき。
